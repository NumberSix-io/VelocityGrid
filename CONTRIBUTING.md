# Contributing to VelocityGrid

Issues and pull requests are welcome, especially with a reproducible workload or measurement.

## Workflow

1. Read the root README and relevant feature document.
2. Preserve the core invariants: bounded state, no per-cell ABI calls, no XAML cell tree, cancellation of obsolete work, and provider authority over uncached data.
3. Build Debug x64 and add focused tests.
4. Run both packaged test projects through Visual Studio Test Explorer.
5. Manually verify initial load, wheel/thumb scrolling, keyboard selection, random jumps, streaming updates, and close/reopen.
6. Build Release x64 and benchmark hot-path changes.
7. Update public API comments and documentation in the same change.

Generated C#/WinRT projection files are regenerated by building after an IDL change; do not hand-edit their ABI implementation.

## Style

- C#: nullable enabled, guard public arguments, and XML-document public API.
- C++: C++20, RAII/COM smart pointers, explicit ownership, and `noexcept` where meaningful.
- Explain non-obvious lifecycle, threading, and performance decisions; do not narrate obvious syntax.
- Avoid allocations, locks, and managed callbacks in scrolling/rendering hot paths unless measured.

## Performance pull requests

Include configuration, hardware/display context, scenario, before/after numbers, and metric interpretation. Use Release x64. FPS alone is insufficient because presentation is display-synchronized.

## Checklist

- [ ] Debug and Release x64 build.
- [ ] Relevant tests pass in Test Explorer.
- [ ] Sample manually verified.
- [ ] Public API/docs updated.
- [ ] Hot-path impact measured or explained.
- [ ] No unrelated generated, package, or user-specific files added.
